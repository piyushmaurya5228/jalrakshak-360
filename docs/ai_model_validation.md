# JalRakshak 360 — AI Model Validation Report

## 1. Objective

This document records the baseline evaluation, sensitivity analysis,
and reproducibility testing of the Isolation Forest anomaly detection
component used in JalRakshak 360.

The current evaluation uses a 12-location prototype dataset.
These experiments assess model behaviour and stability, not
real-world predictive accuracy.

## 2. Model Configuration

| Parameter | Configuration |
|---|---|
| Algorithm | Isolation Forest |
| Number of estimators | 200 |
| Default contamination | 0.20 |
| Random state | 42 |
| Input features | 5 |

### Input features

- water_contamination_rate
- rainfall_7d
- rainfall_normal
- groundwater_stress
- previous_contamination

### Prediction interpretation

| Prediction | Meaning |
|---|---|
| -1 | Anomaly detected |
| +1 | Normal observation |

The anomaly score is generated by normalising Isolation Forest
decision scores to a 0–100 scale using the current scoring batch.

It is a relative anomaly indicator, not a probability of contamination.

### Observations

1. Village_G was consistently flagged under all tested settings.
2. Village_F showed relatively high stability across settings.
3. Village_E was sensitive to the contamination threshold.
4. Village_C was flagged only at the 30% setting.
5. The number of flagged observations increased with the contamination setting.

These results demonstrate sensitivity to model configuration.
They do not establish which contamination value is optimal.

## 5. Reproducibility Testing

`tests/test_anomaly_model.py`.

The test trains two models using:

- The same input dataset.
- The same contamination setting.
- The same random state.
- The same number of estimators.

It verifies that both models produce identical anomaly predictions
and normalized anomaly scores.

## 7. Model Limitations

### Small dataset

The current prototype contains only 12 locations.
This is insufficient to establish statewide anomaly detection performance.

### No independent ground-truth labels

Verified expert-reviewed anomaly labels are not currently available.
Therefore, precision, recall, F1-score and accuracy cannot yet be
reliably reported.

### Training and scoring on the same dataset

The current pipeline trains and scores the Isolation Forest
using the same location dataset.

An independent evaluation dataset is required to assess
generalisation.

### Relative anomaly scores

Min-max normalisation is calculated using the current scoring batch.
Consequently, scores can change when the set of evaluated
locations changes.

The normalized anomaly score must not be interpreted
as a probability or a direct measurement of water contamination.

### Contamination parameter

The contamination setting controls the model's assumed
proportion of outliers. It does not represent the actual
contamination rate of drinking-water sources.

## 8. Recommended Future Work

1. Collect a larger verified environmental dataset.
2. Obtain expert-reviewed anomaly labels wherever possible.
3. Separate model training and independent evaluation data.
4. Evaluate temporal and spatial generalisation.
5. Compare Isolation Forest with suitable baseline methods.
6. Evaluate precision, recall and F1-score when reliable labels exist.
7. Study sensitivity to feature selection and missing observations.
8. Monitor data drift and changes in anomaly-score distributions.
9. Document model limitations in the dashboard.

## 9. Conclusion

The current Isolation Forest implementation is reproducible
under a fixed random state and demonstrates consistent anomaly
flags for selected locations across the tested contamination settings.

However, the evaluation is limited to a small prototype dataset.

The model should currently be treated as an experimental
anomaly detection component within the broader explainable
water-risk decision-support system, rather than as an independently
validated drinking-water safety classifier.
